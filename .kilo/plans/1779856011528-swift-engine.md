# Plan: Add Discord Bot Subcommand

## Overview

Add a `discord` subcommand to `lncrawl/app.py` that starts a Discord bot, allowing users to interact with lncrawl (crawl, search, job status) via Discord. Generated e-book files are sent as Discord attachments if within a configurable size limit, otherwise uploaded to file.io with a download link.

## Dependencies

- Add `discord.py` (v2.x) as a new dependency in `pyproject.toml` under `[project.dependencies]`
- Install via `make sync`

## Environment Variables

| Variable | Description | Default |
|---|---|---|
| `DISCORD_TOKEN` | Bot token (required) | — |
| `DISCORD_MAX_FILE_SIZE_MB` | Max file size (MB) for direct Discord upload | `25` |

### 3. `lncrawl/discord_bot/bot.py` (NEW)

Core bot class using `discord.py` v2 `Bot` with `commands` extension:

- **`on_ready`**: Log that the bot is connected, set activity status.
- **`/crawl <url>`** slash command:
  - Accept `url` (required), `range` (optional: `all`, `first N`, `last N`), `format` (optional, default `epub`)
  - Call `ctx.setup()` (idempotent), then `ctx.sources.init_crawler(url)` → `ctx.crawler.fetch_novel()` → fetch chapters → `ctx.binder.make_artifact()`
  - Run the heavy work in a thread pool (`asyncio.to_thread`) to avoid blocking the event loop
  - Send progress updates via `interaction.followup.send`
  - On completion, send the artifact file via `discord.File` if within size limit, else upload to file.io and send the link
- **`/search <query>`** slash command:
  - Accept `query` (required), `source` (optional filter), `limit` (optional, default 10)
  - Reuse search logic from `lncrawl/commands/search/helper.py` (`perform_search`)
  - Format results as a Discord embed with source name, title, URL, and info
- **`/status [job_id]`** slash command:
  - If `job_id` given, query `ctx.jobs.get(job_id)` and display status
  - If no `job_id`, list recent jobs for the admin user via `ctx.jobs`
  - Display as embed with status emoji, novel title, progress info

### 4. `lncrawl/discord_bot/file_upload.py` (NEW)

Utility for file delivery:

- `should_upload_to_discord(file_path, max_size_mb)` — check file size against limit
- `upload_to_fileio(file_path)` — POST to `https://file.io` with multipart form, return the download URL
- `get_file_delivery(file_path, max_size_mb)` — return either `discord.File` or a URL string

## Key Design Decisions

- **Lazy imports**: All `discord.py` imports happen inside the command function, keeping CLI startup fast (consistent with existing patterns in `context.py` and `commands/server.py`).
- **Slash commands**: Use Discord's application commands (slash commands) for better UX with autocomplete and parameter validation.
- **Async architecture**: `discord.py` v2 is async-native. Heavy crawl operations run in `asyncio.to_thread` to avoid blocking the bot's event loop.
- **Single admin user**: The bot uses `ctx.users.get_admin()` as the user identity for all operations, consistent with the CLI crawl command.
- **No per-user auth**: The Discord bot is intended for personal use; all operations run under the admin account.
